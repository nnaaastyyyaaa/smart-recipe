# SmartRecipe

**SmartRecipe** — веб-застосунок, який допомагає вирішити вічне питання «що приготувати?» з тих продуктів, що вже є вдома.

## Навіщо це потрібно

Майже кожен колись стояв перед відкритим холодильником і не розумів, що з усього цього можна приготувати. Пошук рецептів в інтернеті забирає багато часу, а знайдені варіанти рідко збігаються з тим, що є під рукою: то не вистачає одного інгредієнта, то потрібно щось, чого в домі немає.

SmartRecipe розвʼязує цю проблему навпаки: ви не шукаєте рецепт під продукти, а обираєте продукти — і отримуєте страви, які з них справді можна зробити.

## Як це працює

1. **Почніть генерацію.** Авторизований користувач натискає «Почати генерацію» — створюється нова сесія створення рецепта.
2. **Оберіть дієтичні обмеження.** Щоразу на початку потрібно обрати обмеження (наприклад, веганське чи без глютену) або вказати, що їх немає. Обмеження не зберігаються в профілі й запитуються знову для кожного нового рецепта.
3. **Оберіть продукти.** Ви відмічаєте те, що є вдома. Показуються лише продукти, що підходять під обрані обмеження. Продукти зручно шукати й фільтрувати за категоріями.
4. **Отримайте ідеї.** Застосунок пропонує до 16 страв — лише назви та невеликий опис. Варіанти показуються по 8 на сторінці, між сторінками можна перемикатися.
5. **Виберіть страву.** Коли щось сподобалось, ви обираєте цей варіант.
6. **Отримайте повний рецепт.** Для обраної страви складається докладний рецепт: список інгредієнтів із пропорціями, час приготування та покрокова інструкція.
7. **Збережіть собі.** Рецепти, які сподобались, можна додати до власної «Кулінарної книги», повернутися до них пізніше або прибрати, коли вони більше не потрібні.

Ідеї страв і рецепти створює штучний інтелект (Google Gemini), тому щоразу варіанти підбираються саме під ваш набір продуктів та обрані обмеження. Уся відповідь надається українською мовою.

## Інтеграція проєкту

Інтеграцію виконано локально із використанням Docker: уся система (бекенд, база даних і фронтенд) запускається через Docker Compose, що забезпечує однакове середовище для кожного учасника команди та незалежність від налаштувань окремої машини.

Бекенд побудовано на FastAPI за принципами DDD (шари presentation, application, domain та infrastructure), фронтенд — односторінковий застосунок (SPA) на React, який отримує всі дані від бекенду через REST API.

### Інтегровані компоненти

| Компонент                | Призначення                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Бекенд-сервіс (REST API) | Бізнес-логіка: авторизація, сесії генерації рецептів, дієтичні обмеження, продукти, ідеї страв, рецепти, «Кулінарна книга»                 |
| PostgreSQL               | Зберігання даних користувачів, продуктів, збережених рецептів. Доступ — через асинхронний SQLAlchemy, зміни схеми — через міграції Alembic |
| Google Gemini            | Зовнішній ШІ-сервіс, який генерує ідеї страв і повні рецепти українською мовою                                                             |
| Фронтенд (React SPA)     | Інтерфейс користувача: реєстрація і вхід, профіль, етапи генерації рецепта, «Кулінарна книга»                                              |

Точки інтеграції:

- **бекенд ↔ PostgreSQL** — збереження та читання даних, міграції схеми;
- **бекенд ↔ Google Gemini** — формування запиту на основі обраних продуктів і обмежень та обробка відповіді;
- **бекенд ↔ фронтенд** — взаємодія через REST API, авторизація — JWT у HttpOnly cookie.

### Управління залежностями

- Залежності бекенду описані у файлі `backend/requirements.txt`, фронтенду — у `frontend/package.json` і `frontend/package-lock.json`.
- Версії залежностей зафіксовані, щоб збірка була відтворюваною та не виникало конфліктів між учасниками команди.
- Залежності встановлюються під час збірки Docker-образів, тож для запуску не потрібно нічого встановлювати вручну на хост-машині.
- Ключі доступу (зокрема до Google Gemini) та параметри підключення до бази даних передаються через змінні середовища й не зберігаються в репозиторії.

### Запуск проєкту

Перед першим запуском у корені проєкту потрібно створити файл `.env` зі змінними `GEMINI_API_KEY`, `GEMINI_MODEL` і `JWT_SECRET`.

```bash
# Зібрати образи та запустити всі контейнери (база даних, бекенд, фронтенд)
docker compose up -d --build

# Застосунок: http://localhost:3000
# Документація API:   http://localhost:8000/docs

# Перевірити стан контейнерів
docker compose ps

# Зупинити систему
docker compose down
```

### Запуск бекенду

```bash
# Запустити лише базу даних і бекенд
npm run start:backend

# Переглянути логи бекенду
docker compose logs -f backend
```

### Запуск фронтенду

Фронтенд можна запустити окремо без Docker, якщо бекенд уже працює. Бекенд приймає запити лише з порту 3000, тому контейнер фронтенду перед цим потрібно зупинити (`docker compose stop frontend`).

```bash
# Запустити базу даних і бекенд у фоні
docker compose up -d db backend

cd frontend
npm ci
npx vite --port 3000
```

Застосунок буде доступний за адресою http://localhost:3000.

### Результат

Проєкт інтегровано в єдину систему: бекенд, база даних і фронтенд зібрані в Docker-середовищі та запускаються однією командою. Бекенд взаємодіє з базою даних і зовнішнім ШІ-сервісом, фронтенд отримує всі дані через його REST API. Разом компоненти реалізують описані функціональні вимоги — від вибору обмежень і продуктів до збереження рецепта в «Кулінарній книзі».
